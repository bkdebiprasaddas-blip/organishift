## 3. Work Done (File-by-file delta)

**BC-1 — TaskDetailDrawer dialog effect dead after mount (HIGH, regression from 2026-09-02 session):**
- `client/src/components/common/TaskDetailDrawer.jsx`: effect dep array `[]` → `[isOpen]`. Root cause: the 2026-09-02 session changed this from `[isOpen, item, onClose]` to `[]` intending to fix a different bug (refocus-per-render), but `TaskDetailDrawer` is *always mounted* by `EventExecution.jsx` (prop-driven `isOpen`, not conditional JSX mounting like `Modal`) — so `[]` meant the effect only ever ran once, on initial mount while `isOpen` was still `false`. Escape/focus-trap/scroll-lock never activated on any real open. Fixed to `[isOpen]` specifically (not `[isOpen, item]`) so it re-runs on open/close but not on every in-place item update while the drawer stays open (which would reintroduce the original refocus bug).

**BC-2 — Status dropdown ownership check inconsistent with row checkbox (MEDIUM):**
- `client/src/pages/EventExecution.jsx`: `canEditStatus` (status `<select>` in `renderActions`) now uses `ownedNodeIds` (owns self or any ancestor), matching `canToggleStatus` (the row checkbox). Previously it only checked direct `assigneeId` match — a MEMBER who owns a parent branch could complete a child via the checkbox but couldn't see the dropdown to set BLOCKED, even though the server already allowed it.

**BC-3 — "Library"/"Custom" badge in Event Plans builder always wrong (MEDIUM):**
- `client/src/pages/EventPlans.jsx`: `node.source === 'LIBRARY'` → `!!node.sourceLibraryItemId`. The server has never sent a `source` field (real field is `sourceLibraryItemId`), so every plan module was mislabeled "Custom" regardless of origin.

**BC-4 — `/api/event-items` alternate route mount aliased Event ops, not item ops (LOW-MEDIUM):**
- `server/src/server.js`: removed `app.use('/api/event-items', eventRoutes)`. Confirmed via grep unused by client and tests before removing. The mount had exposed `PUT/DELETE /api/event-items/:id` as `updateEvent`/`deleteEvent` (Event, not EventItem) — a landmine for future API consumers.

**BC-5 — `GET /events/:id/progress` wrote to DB on every call (LOW-MEDIUM, incomplete SV-H4):**
- `server/src/services/progressService.js`: `recalculate(eventId, session, user, opts)` now takes `{ persist = true }`. When `false`, computes progress in-memory and decorates the response without calling `.save()`/`findByIdAndUpdate`. Bonus fix: the empty-items early return now returns `{ eventProgress: 0, tree: [] }` instead of the previously inconsistent `{ eventProgress: 0, items: [] }` (main path always returned `tree`).
- `server/src/controllers/eventController.js`: `getEventProgress` now calls `recalculate(id, null, req.user, { persist: false })`. All other callers (schedule/add/update/delete item) keep default `persist: true` — unchanged behavior.

**BC-6 — Delete-confirmation "…and N more" math wrong for nested branches (LOW):**
- `client/src/pages/PlanningLibrary.jsx`: confirmation dialog previously mixed a deep descendant count (`confirm.total`) with a shallow direct-children listing, producing a nonsensical residual count for any nested branch. Now states the deep total in the intro sentence and computes "…and N more" from `confirm.node.children.length` (matching what's actually listed).

**BC-7 — Calendar start-date picker allowed past dates (LOW, UX nit):**
- `client/src/pages/Calendar.jsx`: added `min={new Date().toISOString().slice(0,10)}` to the Schedule Event start-date input, matching the server's past-date rejection instead of only surfacing it after submit.

## 5. Decisions
- BC-1 fix targets `[isOpen]` specifically, not `[isOpen, item]` — including `item` would re-fire the effect (and yank focus to the first field) on every autosave while the drawer stays open, since `EventExecution.jsx`'s `onUpdate` handler replaces `activeDrawerItem` in place after each field save.
- BC-5: chose "compute always, persist conditionally" over duplicating the calculation logic for a read-only path — keeps a single source of truth for the progress algorithm.
- BC-4: removed the alternate mount outright rather than scoping it to only the item sub-routes, since it was already unused and the item routes are already reachable at their real path under `/api/events`.
