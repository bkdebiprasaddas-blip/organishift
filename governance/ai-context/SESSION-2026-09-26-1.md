# Technical Session Log: SESSION-2026-09-26-1.md

## 1. Objective
Full page-by-page audit of OrganiShift for bugs, vulnerabilities and broken
functions, then fix everything found. Follow-up sessions closed the remaining
performance/robustness items and the documentation drift the fixes introduced.

## 2. Environment Facts
Unchanged from SESSION-2026-09-25-1 (Windows 11 / PowerShell, Node v24.18.0,
npm 11.16.0, MongoDB 8.3 service). One addition: ESLint 9 flat config added to
`client/` (the `lint` script existed but had no config or dependency, so it
could never run).

## 3. What was audited
All 68 source files (~4.5k lines) read in full: every file under
`server/src/{config,controllers,middleware,models,routes,services,utils}`, every
file under `client/src/{components,context,pages,services,utils}`, both test
suites, `server/scripts/`, and the docs. Not code changes at audit time.

## 4. Findings and fixes

### 4.1 CRITICAL — Event Execution page was 100% non-functional
`EventExecution.jsx` called `useMemo` AFTER two early returns. Render #1
returned at the `!data` guard; render #2 (post-fetch) then added a 14th hook, so
React threw *"Rendered more hooks than during the previous render"* on every
navigation to `/events/:id`. Reachable from Dashboard, Execution Hub and
Calendar, so the page was dead from all three entry points. Hook moved above the
returns.

### 4.2 CRITICAL — dates read in the wrong timezone (one root cause, 3 symptoms)
Every date field (`Event.startDate/endDate`, `EventItem.dueDate`) is a *calendar
date* chosen in an `<input type="date">` and persisted as UTC midnight, but was
read with local-time getters:
- tasks flagged `OVERDUE` on their own due date (west of Greenwich)
- Calendar dropped events into the previous day's cell
- `POST /api/events` rejected same-day scheduling ("Start date cannot be in the
  past") east of Greenwich, making the date picker's own `min` attribute a lie

Fix: new `client/src/utils/dates.js` + `server/src/utils/dateOnly.js`; both
sides read/compare UTC calendar days. `localDateKey` exists for the Calendar
month grid (browser-produced local midnights) while `utcDateKey` is used for the
persisted values.

### 4.3 CRITICAL — `JWT_SECRET` fail-closed guard was defeated by its own default
`config/env.js` tested `NODE_ENV !== 'development'` while `NODE_ENV` itself
defaults to `development`. A deploy setting neither variable skipped the guard
and signed tokens with `dev-only-insecure-secret-change-me` — a literal public
in this repository, so anyone could forge an ADMIN token. Now: always throws when
absent; a supplied secret must be >= 16 chars; documented placeholders are
rejected under `NODE_ENV=production`; the dev fallback needs an explicit
`ALLOW_INSECURE_DEV_SECRET=true` and is ignored outside development.
Verified across 4 scenarios with `dotenv` neutralised so the local `.env` could
not mask the result.

### 4.4 HIGH — comment authorship was rewritten on every save
`updateExecutionItem` stamped `user`/`userName` onto EVERY entry of the comments
array. The client always PUTs the whole array, so the next person to comment
silently re-attributed everyone else's comments to themselves. Now existing
comments (matched by `_id`, which the Zod schema now declares so it is not
stripped) keep their original author and timestamp.

### 4.5 HIGH — TaskDetailDrawer autosave destroyed unsaved edits
The field-seeding effect depended on `item`, but the parent replaces that object
on every successful autosave, so saving one field reset all the others to their
last-fetched values. Typing in Description then clicking "+ Add" tag silently
discarded the description. Now keyed on the task id, reading the latest `item`
through a ref.

### 4.6 HIGH — `GET /api/events` had no role scoping
Any authenticated user saw every event, unlike `dashboardController` which
explicitly restricts MEMBERs (SV-M10). A MEMBER landing on an unrelated event got
an empty "No checklist items" page. Now scoped, plus a bounded `limit`.

### 4.7 HIGH — MEMBER read-only library was a 403 dead end
`PlanningLibrary` is reachable by MANAGER and advertises a read-only view, but
every row opened an editor whose Save / Add Sub-folder / Add Sub-task / Delete
all returned 403. Inputs are now read-only with an inline notice and mutating
controls hidden.

### 4.8 HIGH — status auto-chain double-fired
Clicking a `NOT_STARTED` checkbox fired the whole `IN_PROGRESS -> COMPLETED`
chain twice on a double-click, interleaving statuses, and the `.then()` had no
rejection handler. Now a per-item in-flight guard plus a terminal `.catch`.

### 4.9 MEDIUM/HIGH — Dashboard torn itself down on a background refresh failure
`load(true)` set `error` unconditionally and the render treated any `error` as
fatal, so one failed refetch destroyed six counters, the work list and the events
list. Now only fatal when there is no data yet.

### 4.10 MEDIUM — assorted
- Zod per-field `details` were returned but never rendered; every validation
  failure read "Validation failed" with no field named.
- `onRetry={load}` passed a MouseEvent as the `silent` flag (truthy → loading
  state skipped, empty tree flashed).
- `ConfirmDialog` in `EventPlans` had no `busy` prop → double-click issued two
  DELETEs and a bogus "Delete failed" toast.
- `Layout` fetched `/api/events/:id` as a "fallback", duplicating the request
  `EventExecution` already makes, and swallowed failures so the breadcrumb could
  stick on "Event Execution" permanently. Now only subscribes to
  `EventTitleContext`; that required stabilising the context value with
  `useMemo`, and depending on the stable `setTitle` rather than the whole
  context object (which would have re-fired the effect and double-fetched).
- `createPlan` swallowed its refetch error, so a just-created plan could appear
  to vanish. Now inserts into local state.
- `loadPlanItems` had no cancellation guard → stale response could overwrite a
  newer plan's tree.
- `upcomingEvents` had no date filter; `myWork` was silently capped at 20;
  `GET /events/:id/progress` returned 200 for an unknown event id.
- Login: `App.jsx` passed `state.from` but `Login` hardcoded `/dashboard`, so the
  intended page was always discarded; the captured path also dropped the query
  string. Now honoured, with an open-redirect guard (`^\/(?!\/)`).
- Zod validation on comments: `_id` added to the schema (Zod strips unknown
  keys), and the ADMIN/MANAGER field gate was confirmed **intentional** (T-05).

### 4.11 PERF — quadratic MEMBER scoping
`scopeItemsForMember` looped all items once per assigned item. It runs on every
`/events/:id`, `/dashboard/stats` and `/events/:id/progress` request. Measured
worst case (every node assigned):

| items | before | after | speedup |
|---|---|---|---|
| 200 | 1.56ms | 0.39ms | 4x |
| 1000 | 34.16ms | 1.47ms | 23x |
| 5000 | 478.67ms | 6.77ms | 71x |
| 20000 | 12811.56ms | 30.10ms | 426x |

Rewritten as one pass over each item's own ancestor chain. T-18c runs the OLD
implementation as a differential oracle over 300 randomised trees x 3 users to
prove behavioural equivalence.

### 4.12 PERF — progress writes and N+1
`recalculate` did one `item.save()` per item (15+ round trips to tick one
checkbox) and, because `EventItem` has `optimisticConcurrency`, those saves
bumped `__v` on *derived* data. Since `updateExecutionItem` filters on
`{_id, __v}`, persisting progress could invalidate a concurrent editor's token
and hand them a spurious 409 for an edit to a different branch. Now a single
`bulkWrite` of only genuinely changed nodes, filtering on `_id` only.

`copyFromLibrary` and `scheduleFromPlan` re-queried the parent document inside the
creation loop to read a `path`/`level` they had just written. Now carried in a
local map:

- `copyFromLibrary` 22 → 14 db commands (6 library nodes)
- `scheduleFromPlan` 23 → 15 db commands (9 plan nodes)

(Verified by stashing the change and re-measuring against the old code.)

### 4.13 CONFIG — trust proxy
Behind a reverse proxy every request appears to come from the proxy, so
`express-rate-limit` buckets all clients into one address and a single abusive
client can lock everyone out of `/auth/login`. Opt-in via `TRUST_PROXY` (unset by
default, so local dev is unaffected). Deliberately not `true` by default — that
would trust `X-Forwarded-For` from any caller and let clients spoof their IP to
bypass the login limiter. `true` coerces to one hop.

## 5. Decisions
- **Reverted the "ADMIN privilege inversion".** Initially widened the
  `assigneeId`/`priority`/`dueDate` gate from MANAGER to ADMIN. Test `T-05`
  ("Admin owns structure, not operations") failed, and `DEMO-SCRIPT.md` step 12
  plus `dod-rehearsal.js` step 12 both document the 403 as intended. Reverted the
  server change, reverted the client gates, and left comments in both places
  saying not to widen it without changing that test.
- **Rejected my own hypothesis about `__v`.** Suspected `recalculate` bumped
  `__v` on every item, causing spurious 409s. A runtime probe showed only nodes
  whose progress actually changed were bumped. Dropped rather than reported a
  false positive.
- **Regression introduced then fixed:** stabilising `EventTitleContext` with
  `useMemo` changed the context identity, and `load` depended on the whole
  object, so `useEffect([load])` re-fired and double-fetched `/api/events/:id` —
  replacing the Layout double-fetch with a different one. Fixed by depending on
  the stable `setTitle`.
- **H-17 test rewritten.** It asserted its date filtering through a MEMBER token,
  which only returned rows *because* `/api/events` did not scope by role. Now
  uses an admin token (matching what it was written to test) and SV-M10b covers
  the scoping.
- **Date-dependent fixtures.** The same rot had already broken SV-M13 and
  `dod-rehearsal.js`. All scheduling fixtures now derive from
  `futureDateKey(days)`, including the remaining 2030 literals.

## 9. Open / Not Done
- **Non-functional requirements are still undefined** (§J15A): no accessibility
  target, no response-time budget, no RPO/RTO, no backup/restore verification,
  no rate-limit budget. These are undefined, not "production ready".
- **Stateless JWT with no revocation** (documented as Medium in
  `PROJECT-ARCHITECTURE.md`): logout is client-side only; a token is valid for 24h
  after deactivation. Needs a token version or short-lived + refresh.
- **`OrganiShift.bat` has an unbounded wait loop** — if the server fails to start
  it spins forever with no timeout and no error surfaced.
- **No pagination** on `/api/events` beyond the new `limit`, `/event-plans`, or
  `/planning-items`.
- **No CI.** All verification is local; per §J0P/J15G a local pass does not prove
  a production-like environment behaves the same.
