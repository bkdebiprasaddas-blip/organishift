# Work Log — 2026-09-04

## What I set out to do
Do a fresh, independent line-by-line read of the whole OrganiShift codebase (every file in `server/src` and `client/src`) to understand it deeply and find any bugs or UI/UX issues the 2026-08-31 audit missed — then fix them one at a time, updating a checklist as I went.

## What I did
1. Read every server and client source file end to end against the current code (not the old audit's notes).
2. Found and reported 7 new issues, plus corrected a few stale checkboxes in the old audit doc.
3. Created `governance/documentation/BUG_CHECKLIST_2026-09-04.md` listing all 7.
4. Fixed all 7, one at a time, checking each off as it landed:
   - **BC-1 (highest impact):** the task detail side-drawer's "Escape closes it / can't tab out of it / background locks" behavior was silently dead — it only ever ran once, right when the page loaded, and never again when actually opening the drawer. Turns out last session's fix for a different bug accidentally caused this one. Fixed.
   - **BC-2:** a team member who's assigned a whole folder (not a specific task) could tick a checkbox to mark a sub-task done, but couldn't use the dropdown to mark it "blocked" — inconsistent. Fixed so both controls agree.
   - **BC-3:** in the Event Plan builder, every module was labeled "Custom" even when it was actually imported from the shared Library — a leftover-field bug. Fixed the label logic.
   - **BC-4:** removed a confusing, unused duplicate API route that could've silently deleted the wrong thing if anyone had used it.
   - **BC-5:** the "view progress" API call was quietly re-writing progress data to the database on every single view, even for people just looking. Now it only computes and returns; only actual edits write.
   - **BC-6:** the delete-confirmation popup showed a wrong "and N more items" count for nested folders. Fixed the math.
   - **BC-7:** the "schedule event" date picker let you pick a date in the past even though the server would reject it. Added the same restriction to the picker itself.

## Decisions
- Fix targets chosen conservatively — e.g. BC-1's effect now depends on `[isOpen]` only, deliberately not `[item]`, to avoid reintroducing an earlier "cursor jumps while typing" bug.
- BC-4: removed the duplicate route entirely rather than partially fixing it, since it was confirmed unused.
- BC-5: kept one shared calculation function, just made the "save to database" part optional.
