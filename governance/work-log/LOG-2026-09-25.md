# Work Log — 2026-09-25

## What I set out to do
Add developer quick-login test user buttons below the login form on the Login
page, so a developer can click one of the seeded demo accounts to pre-fill the
email and password fields (instead of typing them every time).

## What I did
Edited `client/src/pages/Login.jsx` to add a "Developer quick-login" section
right below the existing Sign in button. The section lists three buttons —
ADMIN, MANAGER, MEMBER — one per seeded role. Clicking a button fills the
email field with its seeded demo address and the password field with
`Password123!`, so the developer just taps the existing "Sign in" button.

This is a UI convenience only: it does not auto-submit or bypass the normal
auth flow, so server-side login + error handling is exercised exactly as usual.
The password string is shown once below the buttons in a small, de-emphasized
hint line so it's copyable but not the visual focus.

No server-side change → no DB or seed-file change; the four seeded demo users
already exist (admin@organishift.dev, manager@organishift.dev,
member1@organishift.dev, member2@organishift.dev, all `Password123!`).

## Decisions
- Pre-fill, then click Sign In — not an auto-submit. Keeps the login flow and
  error handling untouched; the button is purely a faster way to enter creds.
- One button per *role* bucket (ADMIN/MANAGER/MEMBER), not per individual
  user. member1 and member2 are both MEMBER role, so one MEMBER button covers
  both; no value in a second MEMBER button that fills the same password.
- Only seeded LOCAL credentials shown (not the `test.com` account used by the
  acceptance test suite) — those test accounts don't exist in a normal local DB.
- Styled with the page's existing slate/indigo palette so it reads as part of
  the page, not a jarring add-on.
