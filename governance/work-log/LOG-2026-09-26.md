# Work Log — 2026-09-26

## What I set out to do
Go through the whole project page by page and find any issues, vulnerabilities,
broken functions and bugs — then list them, then fix them one by one. Finish by
tidying up the remaining loose ends.

## What I found
Roughly 40 issues across 8 pages, the API layer and the config. The worst one:
the **Event Execution page was completely broken** — a React hooks rule was
violated (a `useMemo` sat below two early `return` statements), so opening any
event threw an error and blanked the page. You could not get into it from the
Dashboard, the Execution Hub or the Calendar.

Two more that mattered a lot in real use:
- **Dates were being read in the wrong timezone.** Every date you pick is stored
  as UTC midnight but was being read as local time, so tasks showed a red
  **OVERDUE** badge on the very day they were due, events appeared on the
  calendar one day early, and same-day scheduling was rejected with "Start date
  cannot be in the past" for anyone east of Greenwich — even though the date
  picker had just allowed that date.
- **The security check on the login secret did not actually work.** It was
  supposed to stop the server starting without a proper secret, but the test it
  used passed when `NODE_ENV` was left unset — which is the most common way to
  deploy by accident. It would then sign login tokens with a secret that is
  written in this repository, meaning anyone could forge an admin login. Now the
  server simply refuses to start without a real secret.

Also: the task-detail drawer deleted your unsaved typing when you saved a
different field; a manager opening the "Reusable Event" library hit a screen
full of buttons that all failed with a permission error; and any member could
see every event in the organisation instead of only their own.

## What I did
- Fixed the Event Execution crash.
- Built one shared way of handling dates on both the server and the client, so
  the timezone problem is fixed everywhere at once instead of in three places.
- Made the server refuse to start without a proper `JWT_SECRET`, and rotated the
  one in your local `.env` to a real random value (it was a short, human-readable
  string rather than random bytes). **You will need to log in again once**,
  because rotating it invalidates the current login.
- Fixed the drawer data loss, the manager library dead end, the missing "cancel"
  protection on the delete buttons, the login redirect that never worked, and a
  page that used to blank out if a background refresh failed.
- Comment authors are no longer overwritten when someone replies to a comment.
- Made the member-only event list actually respect what a member is assigned to.
- Fixed four slow spots. The worst: showing a member their own work took **12.8
  seconds** on a large event (now 30 milliseconds). Ticking one checkbox on the
  checklist was writing to every single row in the event one at a time; now it
  is a single batched write. Two functions were re-reading from the database
  inside a loop; both now just remember what they already have.
- Added a working lint setup. The `npm run lint` command existed but had no
  configuration file or the tool installed, so it had never actually run. It
  now reports zero problems.
- Repaired `dod-rehearsal.js`. It had stopped working (5 of 13 steps) because it
  had a fixed event date that has now passed. This matters because that script
  is your backup if something goes wrong during the viva — it would have failed
  in front of an examiner. It is back to 13/13.
- Fixed a test that had been failing, and made every test date relative to today
  so the same thing cannot rot again.
- Updated the documentation, which had started contradicting the code (it still
  described the login-secret weakness as an accepted risk).

## Decisions
- **I was wrong about one thing and put it right.** I spotted that an ADMIN could
  not assign work while a MANAGER could, and started to "fix" it. A test failed,
  and then I found the same restriction written into your demo script and the
  rehearsal script. It is on purpose — admins manage structure, managers run
  events. I undid my change and left a note in the code so nobody repeats the
  mistake.
- **I also caught myself introducing a new bug.** While making a shared title
  cache stable, I accidentally made the event page load twice. I found it by
  re-checking my own work rather than assuming it was fine.
- Restored the 33 deleted `governance/` files rather than deleting them from the
  repository. Your latest commits are actively adding new files to that folder, so
  the deletions looked left over from an earlier session. Nothing was removed.

## Still to do (not code problems, decisions for you)
- **No CI and no defined service levels.** Nothing states how fast the app should
  be, how accessible it must be, or what happens if the database is lost. I would
  not describe this as "production ready" until those are written down.
- **Logging out does not really log you out.** The token stays valid for 24 hours
  even after logging out or being deactivated. A proper fix means shorter-lived
  tokens with a refresh token, or storing a token version on the user.
- **The launcher `OrganiShift.bat` waits forever** if the server fails to start,
  with no message and no way out other than closing the window.
